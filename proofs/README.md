## 为什么更短的程序都被排除了

1. 八个互异目标都不在初值中，每个目标的首次出现至少占一条指令。任何不超过 15 条的程序至多引入七个既非初值也非目标的不同整数，下文称为辅助数。
2. 搜索允许已经产生的所有数永久可用。任意真实寄存器程序都能被这个模型模拟，重复生成已有值的指令可以跳过。因此在该模型中证明无解，就覆盖了所有合法的 48 寄存器程序。正整数、数值上限和整除条件仍逐次检查。
3. 在每个状态，先生成所有当前可达的目标，直到没有新的可达目标。这些步骤不消耗辅助数名额，也不会使其他值失效。然后枚举用当前数集的一次合法运算可以产生的全部新辅助数。为避免把同一辅助数集合按不同顺序重复搜索，同层按数值排序：一个可行延伸如果会用到当前已有机会生成的多个辅助数，可以先生成其中最小的那个。在后续兄弟分支排除先前的选择仍保留至少一种生成顺序。
4. 剩最后两个辅助数时，暂时允许所有目标都作为操作数。选好第一个辅助数后，每个仍缺少生成方法的目标，必须能用最后一个辅助数与旧值、自身、或倒数第二个辅助数组合产生。如果最后两个辅助数一起产生两个不同目标，它们必是同一对操作数的和、正差、积、整商中两种不同的输出。程序对六种组合逐一解方程。复核器还按题目实际值域枚举第一个操作数和每个目标的全部反推操作数，单独检查这个筛选没有漏掉任何这样的操作数对。所有这些筛选只排除已证明不可行的分支。
5. 七个辅助数的搜索按初始状态的候选值分为 34 片，全部返回 `UNSAT`。各片合计访问 **74,700,636 个展开节点**，该计数包含分片共有的起始节点，不等于程序条数。一次 8 并发运行约 **174 秒**，只计这道题的七辅助数判定。达到节点上限会返回 `UNKNOWN`，复核器拒绝把该结果记为证明。

## scored_0399：最短为 21 条

初值为 3、6、12、16，所有结果均须在 1 至 7,571 之间。11 个目标都不在初值中，每个目标的首次出现至少占一条指令。若有不超过 20 条指令的程序，就至多使用 9 个不同的辅助数。

枚举允许永久保留每个已经算出的数。在每一步先生成全部已可达的目标，再尝试下一个辅助数。对前两个辅助数的可达候选分别按数值升序编号，并按编号取模分为 8 × 16 个分片。已经可达的辅助数可提前生成，因此排除先前同层分支用过的候选，不会遗漏可行的顺序。所有 **128 个分片**均完整返回 `UNSAT`，没有把超时或达到节点上限记为无解；合计展开 **8,584,597,358** 个节点（含分片重复计数的前缀），测试 **1,388,271,743** 个末位候选。因此至少需要 21 条指令。

## 全体题目的下界

在原有目标覆盖计数上，额外限制最先生成的两个辅助数。第一个必须属于初值经目标闭包后的一步可达集合。对每个可能的第一个辅助数重复闭包，再取一步可达辅助数的并集，可以包住第二个辅助数的全部取值。限制这两个取值范围后，在原覆盖公式的每个权重项中，依次从最受限的集合挑选尚未使用的最大权重。集合逐步扩大，交换两个名额的选择即可证明这种贪心给出权重和的上界。零权重的空名额允许保留，仍是安全的上界。

该方法将 235 道题的下界各提高 1 条，总下界从 33,331 增至 33,566。上表四题的穷举再合计提高 22 条。其余开放题的上下界差中位数为 92 条。这个差值表示当前证明的精度，其中有多少条能从可行解中删掉仍待确定。

## 复核

使用 Python 3.12 或更新版本及支持 C++17 和 128 位整数的 GCC 或 Clang。以下命令在仓库根目录执行。使用 `--jobs 1` 可在单工作线程上复核相同的分片。程序会重放提交、重算全量下界、核对四个实例的所有分片及计数，并比对每题上下界。

```bash
g++ -O3 -std=c++17 exact_helpers.cpp -o exact_helpers
python -B verify_optimality.py data/puzzles.csv public-assisted/submission.csv --binary ./exact_helpers --jobs 8
python -B proofs/check_small.py data/puzzles.csv data/practice_puzzles.csv --binary ./exact_helpers
```
