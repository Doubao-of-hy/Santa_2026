## 实验设计

从官方目标数至少 15、公开父本长度至少 150 的 391 题中，按公开父本长度分四组。每组选定 3 道开发题和 6 道留出题，两条路线使用共同题号。对每个父本单独构建数值依赖图。按拿掉某个目标后可消去的指令数排序，取前八个目标单独重建，再选取四组目标，分别尝试两种先后顺序。每题有 16 个待重建目标组。同一组使用相同的保留图和可用数值集合，对照与实验只改变重建方法。[全部组别和逐组结果](windows.jsonl.gz)

令 F 包含初始数值及删除目标后可安全复用的保留值。直接对照先列出 F 内任意两值经过一次合法运算产生的数，再尝试由 F 和这些一步值组合得到目标。尝试成对目标时，先完成的目标及其新产生的中间数可用于第二个目标。两种实验方法都从同一个直接对照开始。

* **共享商** 将目标写成 `t = q × k ± r`。基数 k 取自 F，余项 r 取自 F 或不超过 512 的一步值。先用直接运算重建 q，也可以继续拆解一层。每层按余项代价及商的大小挑选部分候选，双目标可复用任一步骤生成的商或其他中间数。[实现](quotient.cpp)
* **带余因式分解** 对每个保留值 r，尝试正数 `t`、`t − r`、`t + r`、`r − t` 的因子对。在数值上限内分解整数，尝试分别用保留值或最多两步生成两个因子，再相乘并复原目标。至多为 40 个缺失因子追加直接组合搜索。[实现](factor_join.cpp)

新数值图先删除无用运算，再用项目的两种调度方式尝试生成受 48 个寄存器限制的完整程序。只有在完整程序通过本题解释器且实际步数更短时才保留。“可重建”只表示该组的目标可以从规定输入恢复，一题可能有多个这样的组。

## 复核与复跑

将本目录放在本仓库下，准备哈希匹配的官方 `data/puzzles.csv`，保留 Git 提交 `248894967985e4e6a68ec188d8387b9f43056f9b`。下列示例在本目录内执行。第一个命令从 Git 读取冻结父本，应用两份逐题补丁并用两份解释器各重放整表。第二个命令还会以 C++17 重新编译并检查 0145 的 16 个组与存档逐项一致。第三个命令检查全部 36 道题、两个父本、两种方法，并复跑 80 个合成案例。

```sh
python -B verify.py
python -B verify.py --ids 0145 --lanes assisted --engines factor_join
python -B verify.py --ids all
```

有多个本地检出时，可用 `--git-root` 指定含父本提交的仓库，用 `--puzzles` 指定官方文件，用 `--work` 指定可写临时目录，用 `--cxx` 指定 g++ 的路径。本包复用仓库根目录下的整数分解、寄存器调度和解释器。构建品及完整候选表由复核程序在临时目录创建，结束后自动清理。所有实测均在本地 CPU 上完成。
