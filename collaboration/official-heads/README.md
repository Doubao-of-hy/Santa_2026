## 两组启动策略

先用 Rudolph 从零生成一次。目标顺序实验保留这次结果，再各生成四遍。一臂用固定随机排列，另一臂根据本次生成图中的依赖关系调整目标顺序，分别尝试后移独享步骤较多的目标、先计算许多目标共用的中间数、迁移一组相邻目标。两臂分别用项目已有的配方选择器合并本臂的五份生成结果。

字典实验保持目标顺序。让生成器从官方初始值先做一至数步，产生一批实际中间数，并把这些数连同官方初始值作为后续构造器的输入。一臂优先选择在普通启动中被多个目标使用的数，另一臂从相近位长、同构造成本的候选中固定种子抽样。每臂各试五个字典，比较时也保留普通启动的程序。所有前置运算均实际执行，在官方初始状态下重放并检查 48 个寄存器。匹配针对单个辅助数，多个辅助数也能共享前置运算。60 对字典中，52 对的完整前置成本相同。[各组实际前置成本和物理步数](trials.json)

最后用 GoodPJW 的图改写程序做相同处理。本地适配将墙钟时间上限换为每次至多 2,400 次子图替换评估，固定随机种子。另用普通单次生成、相同配方选择和相同改写作为消融。目标顺序实验还保留仅用 180 次评估的中间结果。

## 开发、留出及扩大筛选

开发题为 0680、0012、0573、0324。入选依据为历史 Rudolph 从官方输入生成的程序，已经接近独立上界，现有公开上界仍较短。留出题为 0048、0332、0482、0969、0382、0756、0504、0407，在开发阶段两种字典之间比较结果确定前登记。表中每格为整组实际指令数，越少越好。

| 方法 | 开发 4 题 | 留出 8 题 |
| --- | ---: | ---: |
| 冻结独立程序 | 791 | 1,349 |
| 随机调整目标顺序并收尾 | 799 | 未扩测 |
| 定向调整目标顺序并收尾 | 793 | 未扩测 |
| 随机前置字典并收尾 | 790 | 1,370 |
| 定向前置字典并收尾 | 795 | 1,371 |

随机前置字典在两道开发题产生严格改进。留出阶段的唯一严格改进为 0048，普通单次启动也重现了这三步收益。又对另外 26 道至少 15 个目标、独立长度至少 120、公开上界至少短 7 步、历史普通启动距独立不超过 7 步的题，完整重跑普通启动。合计 4,162 条，经配方选择及定次改写降到 4,096 条，现有独立程序共 4,007 条，逐题均未出现严格改进，因此停止扩大。[筛选规则和 26 道题号](screen-design.json)

## 来源和复跑

Rudolph 由 Alex Chilton 发布，采用 Apache 2.0 许可证。复核 Kaggle 运行 371787656，构造器 C++ 源码和项目已收录的第 8 版逐字节一致，SHA-256 为 `353fb2826bd043e16db77b407f7c68ffcb229e9c0b7ed5c2a09505e7f005477d`。实验实际编译仓库中的 `generative/rudolph.cpp`。公开程序合并代码没有进入生成器。GoodPJW 使用公开第 3 版数据集中单独的 `elfopt.cpp` 源文件，SHA-256 为 `16f12d4963acfe795f89f9632e941fb1aea9d8d8de55ac958a45b17a02881db2`。复跑脚本验证该哈希，只改变停止条件。[Rudolph 原笔记本](https://www.kaggle.com/code/alexchilton/rudolph-the-red-nosed-register-allocator?scriptVersionId=371787656) · [GoodPJW 源码](https://www.kaggle.com/datasets/goodpjw2008/santa-2026-dag-lns-programs/versions/3)

在本仓库中运行下面的命令，路径按实际位置替换。普通验证只需要官方题目、此目录的补丁和具有提交 `98e392cc24e2fb68ecbf649e400d506205273372` 的 Git 仓库。重新搜索还需要 C++17 编译器、Python 和 OR-Tools。实测环境为 Python 3.13.7、OR-Tools 9.15.6755、GCC 16.2。各臂的配方选择器有单组件 0.4 秒时限，不同机器可能得到不同的等价配方。归档补丁的逐条重放与此时限无关。
