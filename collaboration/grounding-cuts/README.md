# 哪些中间值是有限算式库所必需的

冻结独立与公开辅助父本，并从同一仓库的四个历史版本加入可用整数。公开辅助组另含独立程序的整数。库中保留这些整数之间所有合法的单步加减乘除，每题的输入文件和来源随实验保留。两种模型用同一算式库、官方初值和同一整题寄存器编译器，每题每种给 3 秒搜索预算。[输入与分组](design.json)

第一种模型为被选算式规定严格的运算先后关系。第二种只选择允许使用的中间值，并从初值开始反复执行可用算式。遇到一个无法生成的目标时，逐个放开更多中间值，只要该目标仍不可达便保留这个放宽。最终剩余的禁用集合必须至少选中一个成员，才能实现该目标。这个条件可用于排除后续的候选集合。所有目标作为允许值参与计算，每个数第一次作操作数前仍必须已生成。[可达性与选择模型](search.py)

在 100 个小算式库上直接穷举 3,200 种中间值集合，证实 225 个必要集合均成立且包含关系极小。一个含有循环依赖的人工样本从 4 条降到 3 条。在两条来源各 8 道开发题和 16 道留出题上，两种模型都未缩短真实程序。新模型累计生成 8,678 条必要条件，有 8 个题目与来源组合排除了当前有限算式库中的严格改进；次序模型在 21 个组合上作出同一判定。其余未决。两种方法与逐题择短共生成 12 份全量候选，均通过两套解释器。该组搜索到此结束。[小库穷举](small.json) · [开发组](development.json) · [留出组](holdout.json)

```powershell
python -B collaboration/grounding-cuts/check_cuts.py
python -B collaboration/grounding-cuts/compare.py --repo . --puzzles data/puzzles.csv --out work/closure --phase development --jobs 4
```
