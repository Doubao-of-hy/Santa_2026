# 在当前候选上复验共享算式分支

直接采用同仓库 `optimize/shared-recipe-portfolio` 分支的 e24a8e5 实现。在新独立父本（140,813 条）上比较仅使用现有程序中的数与加入独立备用程序，其他条件相同。每题求解预算为 1.5 秒，算法先选算式，再编译为实际的 48 寄存器程序。每次完整输出由两份解释器回放。[作者原实现](https://github.com/Hansen0223/Santa_2026/tree/e24a8e5557434d2a2022fc7c9873e71aab148661) · [两组各 32 题的预先分配](../evidence/scc-fresh-design.json)

开发组两法都把 0680 从 211 降到 210；留出组均无额外改进。后续 1,000 题完整扫描中，多父本还将 0324 从 187 降至 186，使用了来自独立 Wang 搜索父程序的一个新中间值。全量单父本为 140,812 条，全量多父本为 **140,811 条**。这些有限候选库上的求解结论只用于解释搜索覆盖。[0680 程序](bank-dev-win.csv) · [0324 程序](bank-production-win.csv) · [两轮对照与完整扫描](results.json)

随后仅给算法各题本身的公开辅助程序，固定父本 134,385 条。在全部 1,000 题的现有数值集合上重新选择算式，整表长度相同。额外试验允许添加付出指令成本的共享偏移数，沿用同一父本和 1.5 秒预算。[单父本逐项记录](public-incumbent.jsonl.gz)
